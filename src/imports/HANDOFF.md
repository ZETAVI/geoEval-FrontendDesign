## 1. 任务目标
产品【洞点】：面向中小客户的 GEO（生成式引擎优化）应用。主线：
`进入 → 品牌资料 → AI 搜索诊断（4 问题 × 5 平台）→ 诊断报告 → 品牌内容（文章）→ 媒体发布（套餐/精准）→ 积分账户与充值`
当前阶段是**前端设计稿（Vite 工作台）**，不是生产实现。代码仓库 github.com/ZETAVI/GEOEval（私有，集成无法读取 Issues）。
用户的工作方式：先出高质量设计，再逐模块推进；要求**辩证、独立、有深度的思考**；信息不足或没把握时，**先联网搜索最佳实践与优秀案例**再设计；每次改动后要“举一反三”回查同类问题。

## 2. 硬约束（违反会被用户直接指出）
1. 样式只来自 `src/styles/global.css` 的 `--s-*`，经 `src/index.css` 的 `@theme inline` 映射为 Tailwind 类（详见 02-tokens）。**禁止内联 style、裸 hex、自定义 font-family**；只用 `--s-font`。新增 token 需两处都加。
2. 动效用 `motion/react`，沿用 `src/design/motion.tsx` 的 `EASE/SPRING/rise/stagger/CountUp`（详见 05-motion）。用户明确认可现有“细腻、流畅、自然”的手感，要保持。
3. 文案：标题 2–6 字（动词+宾语或功能名），说明 1 句 ≤20 字且写明具体动作；禁用黑话（07-content）。
4. 指标口径：只记录排位，不声称“已判断推荐”（06、11）。
5. 视觉风格“光感构成”：白底、蓝(诊断)/绿(内容)/橙(发布)三服务色、CSS/SVG 自绘插画、轻阴影、克制动效。**不要引入新的视觉语言。**
6. Make Kit `hardcoded-astra-ui` 每轮都会被选中但**无 npm 元数据，装不上**。照 make-kit skill 的指引尝试 reconcile，失败就如实告诉用户并继续用项目 token，不要用公共同名包替代。
7. 项目规则（AGENTS.md）：不改 `main.tsx/App.tsx` 入口结构，不新增无层的全局 CSS reset。

## 6. 经验清单（做每个新页面前过一遍）
1. 先盘点**真实可得的数据**，再选呈现；不要设计数据撑不起的图。
2. 指标/标题彼此不重叠；每个只回答一个问题。
3. 文本和图形分离；图形里只放短符号，长文本放列表或点开后的面板。
4. 同一视觉编码只表达一件事（颜色、位置、大小各司其职）。
5. 总览 → 筛选 → 证据，每步一键可达；选中态用共享指示器滑动。
6. 等待阶段呈现“最终结果的结构”，不放无信息的转圈。
7. 一个区域一个层级，避免把面包屑、状态、操作、标题堆在一起；同一行卡片的顶部元素用固定高度行对齐。
8. 每个状态都要设计：空、加载、部分失败、成功、被门槛锁住（说明原因 + 补救入口）。
9. 改完回头检查同类位置（举一反三），再汇报；汇报要诚实写出**未做/未验证**的部分。
