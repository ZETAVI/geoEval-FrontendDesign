# 14 · 第二轮复盘：按“用户任务”重新归类模块

> 起因：用户评审第 1 轮成品后指出 5 个标志性问题。本文先找共性原因，再给出统一的模块骨架与逐项决定。

## 一、从 5 个问题看到的共性
| # | 表面问题 | 根因 |
|---|---|---|
| 1 | “品牌内容”只是一个写文章向导，资料、文章、历史散落（资料入口还是死按钮） | **按“动作”设计页面，而不是按“用户要管理的对象”** |
| 2 | “内容覆盖”清单靠正则判断文案，做不到也不可信 | 把**系统做不到的验证**包装成界面承诺 |
| 3 | 价格用文本框、范围用文本框 | **控件没有按数据特征选**，全是 input |
| 4 | 发布页只有“选套餐/勾媒体”，媒体库、样例、订单没有位置，媒体只有文字 | 同 1；另外**缺少“媒体资源丰富”的信任表达** |
| 5 | 诊断进度按真实完成数线性走，前期几乎不动 | **进度条只反映数据，没有考虑等待心理** |

## 二、统一的模块骨架（所有服务模块同形）
```
ModuleShell：返回 · 标题 · 一句话 ·（右侧主状态）
  Tabs（≤4，带角标）：对象 A · 对象 B · 记录
  内容区
```
| 模块 | Tab | 说明 |
|---|---|---|
| 品牌内容（橙） | **品牌资料** · **核心文章** | 资料是文章与诊断共同的输入，放在同一模块；TopBar“品牌资料”直达资料 Tab |
| 媒体发布（绿） | **发布方案** · **媒体库** · **发布订单** | 媒体库是唯一的媒体目录；精准发布=在库里挑选；订单管理与记录集中在这里，首页只留最近 2 条 |
| AI 搜索诊断（蓝） | 报告内已有 3 个 Tab | 不改 |

原则：**资料 → 文章 → 发布** 是数据依赖链，页面按“依赖对象”分 Tab，按“下一步”引导。

## 三、逐项决定
1. **品牌资料**：分组表单 + 右侧吸顶“完整度”（诊断必填 / 写文章加强两层，缺项点击跳到字段）。资料齐是诊断的前置；`BrandState` 新增 `setup`。
2. **“内容覆盖”替代方案**（不声称“已验证”）：
   - 写前：**写作目标**（取自诊断缺口，可勾选）+ **将引用的资料**（逐项展示值，缺失项提示“文章会更笼统”，一键去补）。
   - 写后：**生成时引用的资料**（文案固定为“生成时引用，请对照检查”，不写“已覆盖”）+ **发布前自查**（用户自己勾选，是用户的声明，不是系统判断）。
   - 真正的效果验证交给**复测**（订单上线后再诊断），已有闭环。
   - 接入时若后端能返回“事实 → 段落”映射，则点击引用可高亮段落（记录在 13）。
3. **控件按数据选**：

| 数据 | 控件 | 理由 |
|---|---|---|
| 行业（两级，“其他”需说明） | 两步分段选择 | 选项少，可见比下拉快 |
| 地址 | 带建议的 combobox，选中显示“已校验” | 对应高德校验 |
| 主营产品 2–80 字 | 文本域 + 字数计 | |
| 品牌特点 2–6 | 标签输入 + 建议词 + 计数 | |
| 价格参考 | **双滑块 + 数字框 + 单位 + “不公开价格”开关** | 是范围值、相对概念；滑块配文本输入以保精度（NN/g 经验） |
| 目标客户 1–5 | 多选 chips | |
| 品牌定位 | 分段控件 | 4 选 1 |
| 手机 | tel + 11 位校验 | |
4. **媒体发布**：媒体库卡片（Logo、类型、标识、预计上线、价格、样例）；分类=类型 + 标识；“样例”抽屉展示已上线样子；套餐卡展示“覆盖哪些媒体”的 Logo 叠；订单 Tab 带状态筛选与 72 小时说明。
   - **Logo 为占位字标**：真实 Logo 的版权与素材由运营提供，设计里不使用真实商标图。
5. **诊断进度**：每条回答分“采样 → 解析”，20 条并发；条的显示值 = `1-(1-p)^1.8`（前快后慢），汇总完成前封顶 96%，只增不减；条旁保留**真实计数**与**阶段名**；末段加流光证明没卡住；时间只给区间。

## 四、舍弃与待确认
- 历史版本、订单详情页、通知：仍在第 5 阶段。
- 资料改动后旧报告“基于旧资料”的标记：本轮只在资料页给出提示，报告标记待做。
- 套餐/媒体字段（标识、权重、样例）为设计假设，见 13 的核对表。

## 五、诚实声明
本轮没有联网检索工具，设计参考来自已有经验（NN/g 滑块与进度、Canva/Jasper/Shopify 的 Hub 与引用、国内软文平台卡片字段），**未逐条核对线上现状**；请以你的业务认知为准。

## 六、落地状态（本轮已实现）
- `ModuleShell` + 标签页（`ui.tsx`）；品牌内容 = 品牌资料 | 核心文章；媒体发布 = 发布方案 | 媒体库 | 发布订单；首页只留最近 2 笔并带“查看全部”。
- 品牌资料（`Profile.tsx`、`profile.ts`）按上表选控件；价格为双滑块 + 数字框 + 单位 + “不公开价格”；右侧完整度分“做诊断必须 / 写文章更具体”，点击跳字段。`BrandState` 新增 `setup`（资料未齐）。
- “内容覆盖”已删除，改为写前“写作目标 + 将引用的资料”，写后“生成时引用的资料 + 发布前自查”。
- 媒体库（`media.ts`）：10 家占位字标卡片，类型 + 标识筛选，样例抽屉；套餐卡展示 Logo 叠；精准发布在媒体库里勾选。
- 诊断进行中：20 条并发，各自“提问 → 解析”；条显示 `1-(1-p)^1.8`，汇总前封顶 96%，只增不减；旁边是真实“已收齐 n/20”、阶段与流光。
- 仍待办：资料保存后旧报告“基于旧资料”标记、第 2/5 阶段。

## 七、给后端的新增假设（同步到 13）
- 媒体字段：类型、标识（新闻源/可带链接/百度收录/移动端）、预计上线天数、单价、样例标题与摘要、Logo URL。
- 资料完整度清单（必填/加强）由后端返回，前端不写死。
- 若能返回“资料项 → 文章段落”映射，可恢复为点击引用高亮段落。
