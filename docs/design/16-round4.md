## 后端对接补充（见 13-backend-integration.md 口径）
- 媒体：`name / logo / kind / intro / pts / days[min,max]`，其余字段不需要。
- 订单：`mode = pack | precise`；pack 订单 `items` 由运维发布后逐步追加（媒体、上线时间、原文链接），`kinds`、`days` 下单时即有；结算返回 `refunded`。
- 诊断采样流：需要流式接口，推送 `{platform, question, text, ts}`；前端仅追加显示。
- 文章风格参数：`angle, readers[], focus, tone, structure, titleStyle, length, avoid[]`。
- 工单：消息类型 `me | agent | system`，可带 `files[]`；需要 `resolve` 与 `reopen` 动作、关联订单 ID、通知中带 `ref`。

## 第 6 轮

按“用户心智”重新梳理：每个服务有一套完整配色（诊断蓝、内容橙、发布薄荷绿），强调字、选中态、进度、按钮都走 `accent` 系列令牌，同一页面不再混入其他服务色。

| 项 | 处理 |
|---|---|
| 配色令牌 | 新增 `accent-ink`（强调字色：诊断=brand，内容=orange-deep，发布=mint）与 `orange-deep`。选中 chip、必填标记、Tab 当前项、金额数字、首页主指标均使用服务色；`ModuleShell` 顶部加服务色渐变与“第 N 步”标签。 |

| 品牌特点 | 标签用统一 `Chip`，“自定义”变为行内虚线 chip，点开即输入；已选项为卡片：状态图标、40 字上限与计数、示例占位、“填入示例”、Enter 跳到下一项、可移除；汇总行用强调色数字。 |

### 后端对接补充
- 媒体详情：需要 `fit`（适合发什么）、`rules[]`（文章长度、外链、审核方式）；目前为前端按类别写死的示例，见 `media.ts` 的 `KIND_FACTS`。
- 采样流：若接口一次性返回 20 条回答，由前端按到达顺序串行回放；若支持流式，每条需带 `platform, question, text[], rank, ts`。
