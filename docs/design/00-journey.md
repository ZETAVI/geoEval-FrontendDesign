# 00 · 终端客户旅程、页面结构与状态

来源：
- 仓库 `docs/product/glossary.md`：术语权威，界面文案以它为准。
- Codex 交互线框 `src/imports/service-entry-wireframes.html`：页面结构、场景和状态的参考基线。

本文件沿用线框中已经设计好的结构和状态，并标出计划在重构中改进的地方（**▲ 改进**）。

## 心智模型
一个以**当前品牌**为主语的服务首页，入口是三大服务：

```
            ┌─ 发现与理解 · AI 搜索诊断 ─┐
品牌服务首页 ├─ 表达与内容 · 品牌内容 ────┤ → 媒体发布后，在发布记录中追踪结果
            └─ 连接与传播 · 媒体发布 ────┘
账户层（横跨品牌）：积分账户 · 通知 · 帮助与客服 · 品牌切换
```
三个服务各有一个强调色：诊断用 brand 蓝，内容用 orange 橙，发布用 mint 绿（文字用 ink 色）。进入某个服务后，整个页面的强调色随之切换。

## 页面地图（线框中的路由）
| 服务 | 页面 | 子视图 |
|---|---|---|
| 首页 | 服务首页 `home` | 三张服务卡、最近发布（可折叠） |
| 诊断 | AI 搜索诊断 `report` | 内容概览 / 平台表现 / 品牌印象 / 回答证据（抽屉） |
| 内容 | 品牌内容 `content` | 品牌资料 `profile` · 当前文章 `article` |
| 发布 | 媒体发布 `publishing` | 套餐发布 · 精准发布 · 媒体资源 · 发布记录 `orders` · 订单详情 `order` · 确认发布方案 `review` |
| 账户 | 积分账户 `points` | 积分明细 / 充值记录 / 发票记录；充值积分、充值详情、开票申请 |
| 账户 | 帮助与客服 | 问题列表 · 提交问题 · 工单会话 |
| 账户 | 通知 | 未读 / 全部，可全部标为已读 |
| 入口 | 登录或注册 | 手机号 + 验证码；首次进入时显示“添加你的第一个品牌” |

服务内页面有一个二级导航（sectionNav）。诊断页的二级项是概览、品牌资料、当前文章；发布页的二级项是套餐、精准、媒体资源、发布记录。**▲ 改进**：把二级导航统一为 Shell 中的同一个组件，线框里各页的写法并不一致。

## 首页的场景状态（线框中的演示场景）
| 场景 | 诊断卡 | 内容卡 | 发布卡 |
|---|---|---|---|
| 没有品牌 | 整页只有“添加你的第一个品牌”引导 | — | — |
| 首次评测（有品牌、无报告） | “了解 AI 如何认识你的品牌” → 进入诊断 | 能力介绍 | 能力介绍 |
| 资料待补充 | 评测还需要补充的项 → 补充资料 | “补充资料后开始写作” | 能力介绍 |
| 可以生成文章 | 本轮推荐指数 3.5 / 5 → 查看评测报告 | “可以开始写作” → 生成文章 | 能力介绍 |
| 已有文章 | 同上 | 当前文章：草稿 / 已确认 | 套餐发布 / 精准发布入口 |
| 有发布订单 | 同上 | 同上 | 同上，并在下方展开“最近发布”（品牌介绍 发布中 2/10 篇） |

服务卡会随数据从“能力介绍”变为“当前结果摘要”，这与 glossary 中 *Terminal-customer service home* 的定义一致。**▲ 改进**：每张卡只保留 1 个主操作；三张卡中“下一步最该做”的那张加上视觉焦点，由品牌状态推导出来。

## 诊断报告
- **内容概览**：
  - 推荐指数（★，如 3.5 / 5）+ 推荐指数说明。
  - 本轮发现，例如“仅 1 个平台提及”，附“查看这组回答”。
  - 回答提及次数。
  - 典型位置 + 典型位置说明（只统计提及品牌的开放回答，取中位位置）。
  - 有效回答数。
  - 最多 2 张优化方向卡：“让特色有具体依据”“补全细分需求下的介绍”，附“查看依据”，在右侧抽屉打开。
- **平台表现**：“具体问题，具体表现”。每行是一个问题（品牌认知 + 需求场景），同一行比较五个平台（豆包、腾讯元宝、DeepSeek、通义千问、文心一言），格子显示第 N 位、提及品牌或未提及品牌，点击打开对应回答的抽屉。
- **品牌印象**：“AI 如何认识品牌”的总述；积极印象和负面与不足，每条都标明条证据数量；同场出现的品牌，附说明“仅来自本轮开放回答，不代表市场排名”。证据不足时显示“本轮证据不足，暂未形成品牌印象”。
- **回答证据**：原始回答，可以展开全文或收起。
- **边界情况**：资料修改后显示提示“资料已更新。本报告保留评测时的信息。”；历史报告为次要入口。
- **▲ 改进**：把四个 Tab 改为“结论 → 印象 → 行动 → 证据”纵向渐进（见 06-ai-patterns）；平台表现网格做成可复用的 ProgressGrid，与评测进度共用。

## 品牌内容
### 品牌资料（五个分区）
品牌与业务 · 门店与联系 · 优势特色 · 客户与价格 · 内容补充
- 行业选择用两级对话框，一级分类 13 个，每个一级分类下都有“其他”。
- 门店位置信息随地点核验自动得出，不额外填写行政区。
- 优势特色选 2–6 项，可以自定义，每项可以补充具体细节（例如“流程明确”补充为“服务前确认清单……”）。
- 客户群体选 2–6 项，价格可填面议；内容补充里填期望定位（“希望用户记住什么”）。
- 资料分为查看态和编辑态，显式点击“保存资料”，保存后给出下一步：去诊断，或去准备内容。
- **▲ 改进**：新建品牌时用 3 步向导收集诊断所需的基础信息；此后的资料维护保持五分区的查看/编辑模式，按分区单独编辑，而不是整页一起进入编辑态。

### 当前文章（状态）
| 状态 | 表现 |
|---|---|
| 门槛：未评测 | “评测后，开始写作” → 开始评测 |
| 门槛：资料不足 | “补充资料后开始写作” → 补充资料 |
| 可生成 | “还没有当前文章” → 生成文章 |
| 生成中 | “文章生成中” |
| 草稿 / 有未保存修改 / 已保存 | 编辑文章、保存修改、重新生成（重新生成在抽屉中确认） |
| 已确认 | 选择发布方式；如果是从发布流程过来的，则显示“返回发布方案” |
- 写作上下文可以在侧边抽屉中查看：品牌资料、评测方向。
- 固定提示：“生成、编辑和确认文章均不扣除积分。”

## 媒体发布
- **套餐发布**：按成功发布篇数选择，在约定的媒体范围内安排，不指定具体平台或账号。
  - 基础覆盖：5 篇，⚡500，门户媒体、地方媒体。
  - 多点分布：10 篇，⚡900。
  - 广泛覆盖：20 篇，⚡1600。
- **精准发布**：按平台和数量选择，平台价格可见；所选平台与数量构成购买约定。
  - 筛选项：媒体分类（央级 / 门户 / 地方 / 垂直 / 内容平台），“更多筛选”里有平台搜索和覆盖范围（国内 / 海外）。
  - 底部汇总条：当前选择，N 篇 · ⚡ 合计。
- **媒体资源**：只供浏览的媒体库，附示例。
- **确认发布方案（review）**：
  - 方案摘要。
  - 用于发布的文章：已确认 / 待确认 / 待准备，未就绪时显示“检查并确认文章”或“准备文章”。
  - 本次使用、可用积分、还差或购买后剩余。
  - 积分不足时“充值后继续”，充值完回到此处。
  - 确认文章后才能“确认购买并发布”，并有二次确认。
- **发布记录**：统计笔数、已发布篇数、处理中笔数；可筛选全部 / 处理中 / 已结束。
- **订单详情**：
  - 状态：待处理 / 发布中 / 协商处理中 / 全部完成 / 已终止·待结算。
  - 发布进度。
  - 购买约定：篇数、积分、媒体范围。
  - 购买时的文章。
  - 发布结果：标题、链接、时间。
  - 订单沟通：联系订单客服或继续订单会话。
  - 申诉期与积分返还结算状态。
- **▲ 改进**：从选择到确认的过程放进一个分步 Sheet，保留独立的 review 页作为深链接；汇总条做成统一的 SelectionBar。

## 积分账户
- 可用积分为所有品牌共用，1 元 = 10 积分。
- **积分明细**：充值到账、积分赠送、套餐发布扣除、发布订单返还，每条都关联业务单号。
- **充值**：可选 ¥100 / 300 / 500 或自定义金额（1–1,000 的整数），支付方式为支付宝或微信支付。
- **充值状态**：待支付 / 确认中 / 充值成功 / 未支付。
- **开票**：
  - 只在充值成功的记录中可以申请开票；到账前显示“到账后可申请”。
  - 抬头为个人或企业；企业需填统一社会信用代码或纳税人识别号（15–20 位）和接收邮箱，并勾选确认信息准确。
  - 状态为处理中 / 待补正 / 已开票；待补正时可以补正后重新提交。
  - 已开票后可以联系客服反馈“未收到发票”。
- **▲ 改进**：开票申请在 Sheet 中完成；三个 Tab 共用同一个 DataList 组件，包括加载、空、错误三种状态。

## 帮助与客服 · 通知
- 工单分订单类和一般类，状态为处理中 / 已解决，以会话形式呈现。订单类工单从订单详情发起。
- 通知每条都有标题、摘要、时间、已读状态和跳转入口，例如“搜索诊断已完成：青禾家政的报告可以查看了”。

## 线框中已覆盖的边界情况（重构时必须保留）
- 读取失败时：说明原因，并提供“重新加载”和返回入口，例如“暂时无法读取订单”。
- 空状态：还没有发布订单、此分类暂无订单、暂无开票申请、本轮证据不足。
- 窄屏布局、长短不一的内容长度、印象条目数量不均（5 项 / 1 项）。
- 支付结果模拟：到账和渠道关闭两种。
- 品牌切换与多品牌共用积分。

## 其他角色（后续阶段）
代理商、运营、管理员复用同一套 Shell 和组件，但各自有独立的导航。每个账号只有一个角色。
