# 03 · 布局、Shell 与自适应

## Shell（终端客户）
```
┌ TopBar：Logo · 品牌切换 ▾ ──────────── 通知 · 品牌资料 · ⚡ 余额 ┐
│                                                                  │
│   <main> 页面容器（max 1200，居中）                               │
│     PageHeader：返回 · 标题 · 一句说明 · 主操作                    │
│     Content                                                      │
└──────────────────────────────────────────────────────────────────┘
```
> 决定（用户确认）：保持单层 TopBar，不做 Sidebar。服务之间的移动靠首页与“下一步”按钮，服务内二级导航待设计。

- 当前品牌是全局上下文，切换时整个页面随之刷新；品牌切换器里同时提供“管理品牌”和“新建品牌”。
- 断点（只有 Shell 用 `@media`）：
  - ≥ 768：完整 TopBar。
  - < 768：TopBar 精简为品牌切换 + 通知 + 余额，主入口移到底部 Tab（首页 / 诊断 / 内容 / 发布，路线图 #8）。
- Shell 的结构在所有页面中保持稳定，页面切换只替换 `<main>` 的内容。

## 服务页骨架 ModuleShell（第 6 轮）
服务色渐变带（`from-accent-soft`）→ eyebrow（“第 N 步 · 服务名”）→ 标题 + 一句话 → Tabs（≤4，当前项 `accent-ink`）→ 内容。主体左主右辅，右栏吸顶。节奏与各页对照见 [17-design-system](17-design-system.md) §3。

## 页面骨架模板
| 模板 | 用于 | 结构 |
|---|---|---|
| `Overview` | 首页 | Hero 与状态摘要 → 服务区块纵向排列 |
| `Report` | 诊断报告 | 结论带 → 双栏（左：内容，右：吸顶目录与行动卡）→ 证据 |
| `Editor` | 品牌资料、内容写作 | 主编辑区 + 右侧上下文栏（报告里的优化方向） |
| `Catalog` | 发布、媒体库 | 筛选（可折叠）+ 卡片网格 + 底部浮动汇总条 |
| `Detail` | 订单、充值、工单 | 状态头 → 进度 → 时间线或列表 → 次要信息 |

## 容器查询（组件级自适应）
- 组件根节点声明 `@container`，内部布局只用 `@sm: @md: @lg:` 这类容器变体，不依赖视口宽度。
- 同一个组件放进窄列或宽主区都要能正常显示，例如 StatTile 在窄容器中从横排变为纵排。
- 网格统一用 `grid-cols-[repeat(auto-fit,minmax(min(100%,280px),1fr))]`，写成一个 pattern 类名 `grid-auto`。

## 空间韵律
- 页面的节奏是：区块间距 48–72、卡片之间 16–24、卡片内边距 20–24。
- 每屏只有一个视觉焦点：只用一张加强卡片或一处服务色大面积填充。
- 信息密度随层级下降而提高：结论层留白多，证据层可以紧凑。
