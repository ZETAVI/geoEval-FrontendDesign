# 17 · 设计系统总览（第 6 轮后的定稿快照）

> 本文是“现在的界面到底是什么样、为什么”的一页式收束。细节仍以 02（token）、05（动效）、07（文案）为准；这里只回答：**新页面怎么做才像同一个产品**。
> 与其他文档冲突时：代码 > 本文 > 旧轮次文档（14/15/16 是历史记录，不再更新）。

## 1. 风格一句话
**光感构成**：白底画布 + 三套服务色（每个服务一整套）+ 自绘 SVG 插画 + 轻阴影 + 克制但有因果的动效。信息先给结论，再给证据；一屏一个焦点；不引入渐变色盘、玻璃拟态等新视觉语言。

## 2. 三套服务配色（第 6 轮的核心结论）
用户心智是“我现在在用哪项服务”，所以颜色表达**服务**，不表达**组件类型**。每个服务页的强调字、选中态、进度、主按钮、Tab 当前项、金额数字都只用本服务的 `accent` 系列。

| 服务 | 色 | `accent` | `accent-soft` | `accent-ink`（强调文字） | 触发方式 |
|---|---|---|---|---|---|
| 诊断（默认） | 蓝 | `--s-brand` | `--s-brand-soft` | `--s-brand` | 默认 |
| 品牌内容 | 橙 | `--s-orange` | `--s-orange-soft` | `--s-orange-deep`（#a8481a，白底可读） | 外层容器 `data-service="content"` |
| 媒体发布 | 薄荷绿 | `--s-mint` | `--s-mint-soft` | `--s-mint` | `data-service="publish"` |

- `Design.tsx` 的 `SERVICE` 表把页面映射到 `data-service`；订单详情属于发布。
- 组件里**只写 `bg-accent` / `bg-accent-soft` / `text-accent-ink` / `border-accent` / `ring-accent/20`**，不要写 `bg-brand`、`bg-orange`、`text-mint`，否则换服务时颜色不跟随。
- 例外：首页要同时展示三项服务，用 `TONE` 表（`Home.tsx`）显式取 `brand / orange / mint` 与对应 `num` 文字色（`text-brand / text-orange-deep / text-mint`）。
- **“你”仍然是橙色**（排位图、同场品牌、报告高亮）。诊断页里橙=你；内容页里橙=服务色；**同一屏不混用**（见 02）。进行中页（诊断服务）的“你”高亮是橙，其余是蓝。
- 危险/短板用 `danger`；优点/成功用 `mint`。订单进度条统一 `mint`（发布服务色）。

## 3. 页面骨架与韵律
所有服务页同一个骨架 `ModuleShell`（`ui.tsx`）：

```
服务色渐变带（from-accent-soft 淡出）
  eyebrow：第 N 步 · 服务名        ← 用户在流程里的位置
  标题（h1） + 一句话说明
  Tabs（≤4，当前项 accent-ink，角标 accent）
内容区（max 1200，区块间距 48–72，卡片间 16–24，卡片内 20–24）
```

页面韵律（每页都按这个节奏，不要自创）：
1. **结论/状态带**在最上，留白最大、字号最大（`text-display / h1`）。
2. **主体**：左主右辅两栏。右栏吸顶（`sticky`），放“完整度 / 汇总 / 回答记录”这类随时要看的上下文。
3. **证据/细节**在最下，默认折叠或点开才看，信息密度最高。
4. 一屏只有一个主操作（填色按钮），其余用描边或文字链。

| 页面 | 左主 | 右辅（吸顶） |
|---|---|---|
| 品牌资料 | 分组表单（Group 带 accent 竖条） | 完整度：诊断必填 / 写文章加强，点击跳字段 |
| 文章写作 | 写作设置 → Tiptap 编辑 → 确认 | 引用的资料 / 文章引用的事实 |
| 媒体发布 | 套餐（档位 + 覆盖面板）/ 媒体库 / 订单 | 汇总条（积分、篇数、条款） |
| 诊断进行中 | 进度条 + 5×4 逐格揭晓表 + “先做别的事” | 回答记录（浅色面板，非视觉重心） |
| 诊断报告 | Hero → Tabs（概览 / 平台排位 / 品牌印象） | 行动卡 |

## 4. 组件清单（先复用，后新增）
| 位置 | 组件 | 要点 |
|---|---|---|
| `kit.tsx` | `Chip` | 全站唯一的选择类控件外观：选中=accent 底+accent-ink 字+对勾；`dashed` 为“添加类”；`role="radio"` 用于单选 |
| `kit.tsx` | `TextField` | 全站唯一输入框：框内计数（≥90% 变 accent-ink、满=danger）、聚焦才出“清除”、accent 聚焦环、`multiline`、`onEnter`（IME 安全，用于跳下一项）、`invalid` |
| `ui.tsx` | `ModuleShell` / `Sheet` / `GateNotice` / `RechargeSheet` / `PayMethod` | 骨架、右侧抽屉、“原因+补救入口”、就地充值 |
| `shared.tsx` | `cx` `AnimatedNumber` `Stars` `Progress` | `Progress` 的 tone 只有 brand/mint |
| `motion.tsx` | `EASE SPRING rise stagger CountUp Parallax useTilt` | 动效基线（见 05） |
| `PublishParts.tsx` | `PackPicker` `MediaDetail` | 套餐=档位选择器+覆盖面板；媒体详情页 |
| `MediaUI.tsx` | `Logo` `MediaLogo` | 占位字标，不用真实商标 |
| `art.tsx` `brand.tsx` | `SearchArt SheetsArt PlaneArt LogoMark LogoField` | 插画与品牌，只在首页和空状态使用 |
| `Editor.tsx` | `RichEditor` | Tiptap；已确认文章编辑要回退草稿 |

**新增控件前**：先看 `Chip` / `TextField` 能不能表达；不能再新增，并回写本表。**不要在页面里再写第三种“选中态”或第二种“输入框”。**

## 5. 层次与信息呈现（做过并被认可的手法）
| 内容类型 | 呈现手法 | 例子 |
|---|---|---|
| 单个结论 | 大数字 + 一句话 + 迷你图形 | 报告四项指标、首页主指标 CountUp |
| 对比选择 | 档位选择器（共享高亮滑动）+ 一块统一详情面板，**不并排三张重复卡** | `PackPicker` |
| 多维数据 | 位置编码（排位图），文本与图形分离 | `PositionMap` |
| 定性内容 | 语言型：一句话画像 + 词云 + 原句 | `Impression` |
| 长列表证据 | 右侧浅色记录面板，可滚动、默认跟随最新、上滑出现“回到最新”、可筛选 | `Running` 的 `Record` |
| 目录型资源 | 卡片网格；整卡可点进详情，选择动作是独立的勾选 | `MediaCard` + `MediaDetail` |
| 等待 | 呈现最终结果的结构（5×4 格逐个揭晓），不放转圈 | `Running` |
| 门槛 | 就地说明原因 + 补救入口（Sheet），完成后留在原页 | `GateNotice` |
| 表单 | 按数据特征选控件（级联、滑块、chips、地图卡），Enter 跳下一项，示例一键填入 | `Profile` |

## 6. 动效手感（已获认可，不要改）
- 入场：`rise` + `stagger`，顺序遵循阅读顺序，总长 ≲ 1.2s。
- 选中态：共享指示器“滑过去”——`layoutId`：`report-tab`、`dot-sel`、`pack-tier`。新增 `layoutId` 必须全局唯一。
- 数字：`CountUp`（进入视口）/ `AnimatedNumber`（值变化）。
- 回放：容器 `key={run}` 重演。
- 页面切换 opacity 0.25s；Tab 内容 y 10→0。
- 循环动画只在“进行中”元素上，完成即停。
- 详见 05-motion；**已知债**：各文件仍散落 0.15–1.6s 十余种时长，新代码只用 05 表里的值。

## 7. 文案（硬约束，07 为准）
标题 2–6 字动词+宾语；说明 1 句 ≤20 字写具体动作；禁用“信息密度、流转、闭环、动作与回应、赋能、让…更具体”。第 6 轮首页三卡是范例：`看 5 个 AI 平台把你排第几 / 写一篇 AI 愿意引用的文章 / 把文章发到媒体，让 AI 找到你`。

## 8. 反模式清单（评审里被指出过的）
1. 同一信息三块并排重复（套餐三卡）→ 改为选择器 + 单面板。
2. 控件全是 input / 选中态各写各的 → `Chip` / `TextField`。
3. 把系统做不到的验证包装成承诺（“内容覆盖”）→ 改为用户自查 + 复测。
4. 数字写死在多个页面 → 一律从 `data.ts` / `diag.ts` / `profile.ts` 派生。
5. 颜色按组件类型选而不按服务选（选中态蓝、按钮橙）→ 全部走 `accent`。
6. 文案写成内部说明（“让信息更具体”）→ 写动作 + 结果。
7. 进度条按真实完成数线性走 → 前快后慢显示值 + 真实计数并存。
8. 回答流做成视觉重心（深色终端）→ 浅色辅助面板，重心留给结果表。
