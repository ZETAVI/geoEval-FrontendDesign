| 根因 | 对应条目 | 处理 |

## 2. 文案规则（硬约束）

1. 标题 2–6 个字：动词 + 宾语（"补全资料"），或具体功能名（"自动保存"）。
2. 说明只有 1 句话，不超过 20 个字，写清具体动作或用户得到的好处。
3. 禁用：信息密度、流转、闭环、动作与回应、赋能、抓手、让……更具体。
4. 有功能就直说功能，例如"自动保存变更"，不写"随时无忧"。
5. 字段提示写"填什么 / 用在哪"，不写"AI 了解你的依据"这类泛述。

## 3. 数据与组件架构

```
data.ts        MEDIA（分类 / 标识 / 预计上线 / 详情）· PACKS · ORDERS（引用 mediaId）
               BRANDS · NOTICES · TICKETS · FAQ
flow.tsx       当前品牌 / 品牌切换 / 订单 / 通知 / 工单
shared.tsx     TopBar（品牌切换、通知、帮助、积分）
```

- "N 家媒体"一律 `MEDIA.length`；首页发布记录、发布页订单、订单详情读同一份 `ORDERS`。
- 订单每一行带 `mediaId`，名称、Logo、预计上线都从 `MEDIA` 取。

## 4. 页面地图（用户思路）

首页 → 诊断（进行中 / 报告）→ 品牌内容（品牌资料 | 文章写作）→ 媒体发布（发布方案 | 媒体库 | 发布订单 → 订单详情）→ 积分；顶栏常驻：品牌切换 · 通知 · 帮助与客服 · 积分。

- 品牌资料：事实（行业、地址、产品、特点及佐证、价格、客群）。
- 文章写作：风格（目的、语气、结构、篇幅、读者）→ 编辑（Tiptap）→ 确认。
- 媒体库：按类别分组；标识有图例；预计上线 = 提交后审核到上线的天数范围；详情抽屉给出介绍、读者、要求、限制、样例。

## 5. 推进顺序

1. 数据层 + 顶栏 + 品牌切换
2. 媒体库与订单详情
3. 品牌资料（行业、地址、价格、特点）
4. 文章写作（Tiptap）
5. 支付、诊断进行中
6. 帮助与通知
7. 文档与验证
