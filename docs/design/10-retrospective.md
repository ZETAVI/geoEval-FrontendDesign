# 10 · 设计复盘与经验（光感构成 · 第一阶段）

这一阶段完成：首页、积分账户、诊断进行中、诊断报告（含平台排位、品牌印象）。用户评价“布局、组件构思、动效、层次”均达到高质量。本文把**为什么这样做**记下来，后续页面按同一思路做。

## 一、用户反馈 → 通用原则（举一反三）
| 具体问题 | 根因 | 通用原则 |
|---|---|---|
| 标题“AI 如何看待青禾家政”空泛 | 写成了概念，而不是功能或收益 | 每个标题/说明都回答“做什么、得到什么”，遵守 07 的 2–6 字 / ≤20 字约束 |
| 报告头部内容堆叠 | 同一区域放了面包屑、状态、操作、标题、元信息 | 一个区域一个层级：顶行=返回+次要操作；标题行=标题+一行元信息；其余下沉 |
| 三个指标“推荐你的平台/提到你的平台/提到你的回答”难懂 | 三个名字实为同一概念的不同计数，用户要自己推导差别 | 指标必须**互相正交**，每个一句话说清，且各配一个直观迷你图形 |
| 平台×问题热力矩阵拥挤、query 被截断 | 用格子承载文本 | 文本和图形分离：问题全文放左侧列表，图形只放符号；长文本放在点开后的证据面板 |
| 数据只有“有/无”，缺推荐程度 | 没解析推荐，但排位本身有信息 | 用已有数据里最强的信号（排位）表达程度，并诚实标注口径 |
| 品牌印象两个进度条，不大气 | 用量化图形表达定性内容 | 定性内容用语言型呈现：一句话画像 + 关键词云 + 原句，大字号、有留白 |
| 首页口号与“建议下一步”错位 | 卡片顶部元素高度不一致 | 同一行卡片顶部使用**固定高度的行**（徽标或“第 N 步”二选一），标题自然对齐 |
| 概览页偏空 | 只放了结论，没把已有数据用满 | 盘点所有可得信息：总评、认知、20 条采样、优化建议 → 各自找到最合适的承载形式 |

## 二、可复用的设计判断
1. **先盘点数据，再选可视化**。能用的数据是：20 条样本 × （排位, 列表总数, 一句描述）。图形必须由这些字段推出，不要设计出数据撑不起的图。
2. **一种视觉编码只表达一件事**：橙色深浅 = 排位靠前程度；位置 = 排位；蓝 = 诊断服务/选中态；绿/红 = 优点/短板。不要同一颜色在两处含义不同。
3. **“你”永远是橙色**：圆点、列表高亮、气泡（气泡里用品牌蓝是个例外，见待改进）统一指向“你在哪里”。
4. **总览 → 筛选 → 证据**三步走，每一步都能一键到下一步：问题行→平台排位 tab（自动聚焦该问题、选中首个命中）→圆点→原文。
5. **等待也是内容**：诊断进行中不放转圈，而是让最终要看的 5×4 格子逐个揭晓，用户在等待时已经在理解结果的结构。
6. **文本图形分离**：图形元素里只放 ≤4 字（`Q1`、`第3位`、`未提及`）。
7. **动效服务于理解**：入场顺序遵循阅读顺序；选中态用共享指示器“滑动”；回放按钮让用户重看过程。
8. **边界说明要克制但必须在**：caption 字号，贴着结论和证据，不做弹窗。

## 三、做法层面的经验
- 数据与口径集中在 `src/design/diag.ts`（单一来源）。指标、档位、问题文案、样本都从这里算，页面不再自行写死数字（待改进项见下）。
- 避免内联 style：离散位置用静态类查表；进度用 SVG `pathLength`；颜色一律走类名。
- 用户同意的方向就沿用：不要再引入新的视觉语言（渐变色盘、玻璃拟态等），在“白底 + 三服务色 + 轻阴影 + 克制动效”内做。
- 每改一块，回头检查同类位置是否有同样问题（标题字数、信息堆叠、指标重叠）。

## 四、已知不足 / 技术债（交接时必须知道）
1. **尚未做浏览器内目视验证**：只通过 `tsc --noEmit` 校验；Home 的卡片顶行对齐、Running 动画节奏、Report 排位图在窄屏的横向滚动，都需要在预览里看一遍。
2. **报告中部分数字是手写的**，没有从 `diag.ts` 推导：Hero 的“3.5 / 5”指数；`Impression.tsx` 的 `THEMES`、`PEERS`（同场品牌次数）、Portrait 文案中的“6 条”；`Report.tsx` 的 `GLANCE`、`DIRECTIONS`。接真实数据前应改为由数据派生。
3. **“AI 推荐指数”的名称与口径不一致**：我们声明“不判断推荐”，但指数仍叫“推荐指数”，公式也只有一句话说明。建议改名（如“AI 可见度”）并写出公式，需产品确认。
4. **同场品牌气泡里“你”是蓝色**，与“你=橙色”的规则不一致；若调整，需同步 Impression.tsx 的 `Peers`。
5. 回答中的其他品牌名与描述来自 `diag.ts` 的 `POOL/NOTES` 模拟数据。
6. `Running.tsx` 的预计剩余时间是估算（每条 9 秒），真实接口应给出剩余时间或百分比。
7. 首页与顶栏的“品牌资料”“通知”入口尚无落地页面。
8. Make Kit `hardcoded-astra-ui` 未能安装；未做联网调研（本阶段设计基于对 shapeof.ai / Linear / Stripe 等模式的既有认识，后续新模块建议先联网核对最佳实践，再设计）。
