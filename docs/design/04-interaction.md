# 04 · 交互规范

## 渐进式暴露（Progressive Disclosure）
| 复杂度 | 手段 |
|---|---|
| 次要操作 | 收进“更多 ⋯”菜单（DropdownMenu）。每个卡片或页头最多只放 1 个主操作和 1 个次操作 |
| 多字段表单 | 字段超过 6 个用分步表单，中等复杂度用 Sheet，确认类操作用 Dialog |
| 过滤项 | 默认只显示 2–3 个常用项，其余放进“更多筛选”折叠区；已生效的筛选以 Chip 形式展示 |
| 细节数据 | 先给摘要，点击后在行内展开或在侧边 Sheet 中查看，不跳页 |
| 历史 | 作为次要入口，不与当前结果平铺在一起 |

## 门槛提示（GateNotice）
被锁住的操作要显示出来，但同时说明原因和解决路径：
> 开始诊断前还需要补充 **2 项**：门店位置、同行特点 → [去补充]

不允许只把按钮置灰、没有任何解释。

## 状态矩阵（每个数据视图都必须覆盖以下状态）
| 状态 | 表现 |
|---|---|
| 首次为空 | 插画 + 价值说明 + 一个主操作 |
| 加载中 | 与最终布局形状一致的骨架屏；200ms 内完成的加载不显示骨架屏 |
| 部分数据 | 已有部分先渲染，未就绪部分显示局部占位 |
| 进行中（长任务） | 真实进度 + 可以离开的提示 + 预计时间 |
| 成功 | 内容本身，重要成功事件额外给一条 Toast |
| 可恢复错误 | 局部错误卡：说明发生了什么，以及“重试”入口 |
| 阻断错误 | 整页错误：说明发生了什么、有什么影响、你能做什么 |
| 无权限 / 已归档 | 只读样式 + 说明 |

## 乐观更新边界
- **允许**（可回滚、低风险）：保存资料字段、标记已读、切换当前品牌、收藏媒体。失败时自动回滚，并用 Toast 提示“未保存，已恢复”。
- **禁止**（涉及钱或不可逆）：提交订单、充值、确认文章、开始评测。必须等服务端确认；按钮进入 loading 状态，重复点击无效。

## 反馈层级
行内校验 < Toast（3–5 秒，可撤销的操作附带“撤销”）< Banner（页级持续状态）< Dialog（需要决定的事）。同一事件只用一个层级反馈。

## 键盘与焦点
- 所有交互元素都能用 Tab 访问，焦点环为 2px `--color-focus` 加 2px 偏移，不能移除。
- Sheet 和 Dialog 打开后焦点困在弹层内，按 Esc 关闭，关闭后焦点回到触发元素。
- 点击热区不小于 40×40，移动端不小于 44×44。
