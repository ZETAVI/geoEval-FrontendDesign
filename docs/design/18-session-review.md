## 二、反复出现的根因（比具体问题更重要）
1. **按“动作/功能”组织界面，而不是按“对象/心智”**（第 2、6 轮）。判断方法：用户在这一页“要管理的东西”是什么？颜色、Tab、文案都应围绕它。
2. **把设计做满而不是做准**（第 4 轮）。每加一个字段/徽章/抽屉，先问后端有没有、用户会不会用。宁可少一层。
3. **承诺系统做不到的事**（第 2 轮“内容覆盖”、“已判断推荐”）。界面只呈现可验证的事实，验证交给复测。
4. **同一概念多处各写各的**（数字、选中态、输入框、颜色）。解药是单一数据源 + 共享控件 + 语义 token。
5. **文案写成内部说明**（第 3、6 轮）。每个标题都要能回答“做什么/得到什么”。
6. **重复的结构被用户一眼看穿**（套餐三张同构卡）。三个同构块 = 应该是“一个选择器 + 一个面板”。

## 三、有效的做法（继续用）
- **先盘点真实数据，再选可视化**；图形里只放短符号，长文本放列表或点开后。
- **一种视觉编码只表达一件事**；颜色表达服务，位置表达排位，大小表达量。
- **总览 → 筛选 → 证据**，每步一键可达，选中态用共享指示器滑动。
- **等待也是内容**：呈现最终结果的结构；回放（1×/3×）让用户掌控节奏。
- **共享控件先于页面**：第 6 轮先写 `kit.tsx` 再改各页，改动面大但风险低、一致性高。
- **每改一处回查同类**：第 6 轮改完 Profile 的 chips 之后，Content、Publish 的筛选同步替换。
- **汇报诚实**：写明未做/未验证（无中文字体、无联网）。
- **后端缺口只记 13，不在前端展开**（用户决定）。

## 四、踩过的坑
| 坑 | 说明 | 避免 |
|---|---|---|
| 预览“旧模块”报错 | 多次出现 `useFlow 需要在 FlowProvider 内使用`、`BADGE_DESC` 未定义等，堆栈行号与当前源码对不上（如报 `Design.tsx:34`，实际在第 20 行）。原因是 Figma Make 预览 HMR 没替换干净 | 先 `grep` 核对源码结构，再用 Chromium 冷加载确认；是 HMR 就让用户刷新预览，**不要为此改代码** |
| `Source data resolution timed out for element DIV/NAV/HEADER` | 预览检查器噪音，不是应用错误 | 直接说明，不处理 |
| `motion.circle` 动画 `r` 无初值 | 控制台反复报 `attribute r: undefined` | SVG 动画属性必须给 `initial` |
| `layoutId` 冲突 | 同名 `layoutId` 会在不同位置间“飞” | 新增时全局唯一（现有：`report-tab`、`dot-sel`、`pack-tier`） |
| 橙色双重含义 | “你/排位”与“内容服务色”撞车 | 同屏不混用；报告里的“去写文章”用蓝色主按钮 |
| 单引号字符串内的撇号 | 构建失败 | 含撇号用双引号 |
| 工作目录漂移 | shell cwd 会重置 | 一律绝对路径 |

## 六、未决债务与风险（按优先级）
**P1：影响真实感/一致性**
1. **动效时长散落**：代码里 0.15–1.6s 约 14 种（`grep -o "duration: [0-9.]*" src/design/*.tsx`）。05 规定的取值之外应归并，新代码不得再引入。
2. **手写数字未全部派生**：`Impression.tsx` 的 `THEMES / PEERS`、Portrait 文案中的“6 条”，`Report.tsx` 的 `GLANCE / DIRECTIONS`（10-retrospective §四.2 当时登记，第 1–6 轮未逐项复核，**接手后先 grep 复核**）。
3. **`KIND_FACTS`（媒体详情的“适合发什么/发布规则”）是按类别写死的示例**，后端是否提供待确认（13）。
4. **诊断状态矩阵未落界面**：空 / 部分失败 / 样本不足 / 被门槛锁定（11-diagnosis 有定义）。
5. **“基于旧资料”标记**：资料保存后旧报告应打标，目前只在资料页有提示。

6a. 服务色残留：`Orders.tsx` 退回积分提示在绿色服务页里用了橙底（违反“颜色=服务”），应改 `danger`/中性。

**P2：体验补全**
6. 首个品牌引导（决定 #9，**未做**）；TopBar 品牌切换已可用，但“新建品牌 → 引导”未接。
7. 移动端：<768 底部 Tab 仅有规范，未实现；中窄屏（768–1100）下的右栏吸顶、Running 双栏、PackPicker 覆盖面板未逐一验证。
8. 统一 `ErrorNotice`（三段式）和骨架屏：规范有，界面基本没有。
9. 可访问性：键盘流、焦点顺序、对比度未做系统审计（`Chip`/`TextField` 已带 aria）。
10. `Running` 的剩余时间是估算；回放总长约 60s 是**演示时序**，真实接口需给 `{platform, question, text[], rank, ts}`。

**P3：工程**

15. 沙箱 Chromium **没有中文字体**：文字显示为方块，只能验证布局/颜色/动效/报错；**字体渲染、中文换行、截断位置未验证**。
