## 一、我理解的终端客户旅程
核心判断：**这不是一个工具面板，而是一个以“当前品牌”为主语、状态逐步推进的服务。** 每个品牌都在一条状态链上，界面的职责是告诉用户“你在哪、下一步是什么、为什么”。

| 阶段 | 用户目标 | 门槛（gate） | 关键状态 |
|---|---|---|---|
| 0 进入 | 注册或登录（短信 + 验证码） | — | 可带代理商归属，客户无感知 |
| 1 建品牌 | 让系统认识我 | 基础信息：两级行业（“其他”需补一句话）、名称、地图选点 + 商圈、主营、2–6 个特点、联系人 | 可存草稿；信息不完整就不能诊断 |
| 2 诊断 | 看 AI 怎么说我 | 基础信息完整；同一版输入只允许一次正式评测 | 4 个问题 × 5 个平台，等待时间长，需要真实进度；成功、失败、重试都要有交代 |
| 3 看懂报告 | 知道问题和方向 | — | 推荐指数（星级，1 位小数）→ 典型位置 → 品牌印象（正/负主题）→ 同场品牌 → 最多 2 张优化方向卡 → 原始回答证据 |
| 4 写内容 | 得到一篇可信的推广文 | 已有评测 + 文章信息（价格、客群、定位等，需显式保存） | 核心文章：草稿 → 确认；确认后再编辑会回到草稿 |
| 5 发布 | 买曝光 | 文章已确认，积分足够（不够就引导充值，1 元 = 10 ⚡） | 两种方式：随机套餐 / 精准选媒体；订单状态：待处理、发布中、异常、完成、关闭，并逐条回传结果链接 |
| 6 账户与售后 | 管钱、问问题 | — | 积分明细、充值订单、开票（个人/企业）、工单（处理中/已解决）、通知中心、72 小时结算 |

## 二、交互重构主张（我的看法）
1. **状态机驱动的“下一步”**：每个品牌在任意时刻只有一个主操作，比如“补全 2 项资料以开始诊断”“查看报告”“确认文章”“选择发布方式”。首页“我的品牌”从“能力介绍”自然过渡到“当前结果摘要”，这正对应 glossary 中的 Terminal-customer service home 定义。
2. **门槛可解释**：被锁住的操作不隐藏也不置灰了事，要直接说明缺什么、点一下就去补（自解释设计）。
3. **报告按四层渐进暴露**：一句结论 + 指数 → 平台表现 → 按问题展开 → 原始回答高亮。证据永远可以追溯，但默认收起。
4. **长任务体验**：评测进度按“平台 × 问题”网格逐格点亮，配合骨架屏和“等待期间你可以先…”的引导。完成后发站内通知，标签页也有提示。
5. **高风险操作用 Sheet 加分步确认**：花费积分、提交订单都要有摘要和二次确认，不做乐观更新；乐观更新只用于保存资料、标记已读这类可回滚操作。
6. **Shell**：左侧窄导航（首页 / 诊断 / 内容 / 发布 / 订单），顶栏放当前品牌切换、⚡ 余额、通知、帮助，移动端改为底部 Tab。代理商、运营、管理员复用同一套 Shell 与组件，但放到后续阶段。
7. **错误文案**遵循 glossary 的 User-facing error message：发生了什么、影响什么、你能做什么。

## 三、推进阶段（每阶段结束停下来让你确认）
0. **补齐**：读取 issue（等权限开通）和关键 spec（customer-entry、evaluation-report、geo-optimization、publishing-commerce、recharge），产出《终端客户旅程与状态图》。
1. **规范文档**，放在 `docs/design/`，每个维度一篇，并在 AGENTS 中加入入口：
   - 架构：React + Tailwind v4 `@theme`、Radix/shadcn 无头原语、Motion、Lucide、sonner、TanStack Query。
   - token：三层结构；满足 WCAG AA。
   - 布局与容器查询。
   - 交互：渐进暴露、状态矩阵、骨架屏、乐观更新边界。
   - 动效：0.98 按压、150/220ms、reduced-motion。
   - AI 结果呈现：参考 shapeof.ai。
   - agent 协作契约。
2. **Shell First**：在 Make 中搭可点击灰盒，覆盖旅程 0–6，先验证视线流和信息容量。
3. **风格发散**：先调研参考站点，再出 2–3 套方案（纸感编辑 / 玻璃光感 / 精密数据），每套覆盖首页、报告、发布、积分；可以探讨首页加入案例。
4. **设计系统定稿**：token 与原语组件，并做组件预览页。
5. **按旅程顺序重建页面**：每个模块一个 issue / PR。

## 决定
- issue 部分跳过（用户确认），以 glossary、spec 与 PR 历史为准。
- `/styles/global.css` 在项目中不存在，token 基线暂定为线框中的 `--s-*`；如果之后提供了该文件，改为以它为准。
- 本轮执行 Phase 0 的剩余部分（读取关键 spec）和 Phase 1（写规范文档），完成后停下，由用户评审。
